# Interactive terminal output audit (follow-up to #1183)

Scope: `chat` (alternate-screen and inline, including runtime switches), `skills browse/add`, `mcp browse`, `sessions browse`, and `config theme`; shared skill/agent/tool/provider/session/MCP/diagnostic workers reachable from those surfaces. Searched Go production code for `fmt.Print*`, `fmt.Fprint*`, `os.Stdout`/`os.Stderr`, builtin `print`/`println`, `log.Print*`, `slog.*`, `exec.Command*` and child `Stdout`/`Stderr` bindings. This is a static audit with regression tests, **not** proof that every dependency or runtime branch is silent.

## Routing policy

- Only when an interactive UI is active, application diagnostics use `internal/runtimeoutput`: a restricted, append-only `$XDG_DATA_HOME/term-llm/diagnostics/tui.log` (or the usual XDG data fallback), with structured slog records enabled and raw provider debug blocks left readable. If it cannot be opened, one warning is shown before UI ownership and diagnostics are discarded for that UI; overlapping ownership remains an error. No CWD fallback is used when HOME/XDG data is unavailable. Debug/raw mode may include sensitive request or subprocess details, so protect and rotate this log as needed (no automatic rotation is currently provided). `Start`/close are scoped to the interactive command; there is no fd replacement or global `log.SetOutput`/`slog.SetDefault`. Outside the UI, direct warnings/debug flags, `log.Printf` and `slog` keep their prior behavior. Lower-level packages do not import Bubble Tea.
- Actionable session-store and chat-runtime warnings go through the existing `tuiWarningWriter` and `FooterNoticeMsg` while the renderer is attached; repeated identical consecutive warnings are collapsed per attachment. During an in-process session switch, synchronous build warnings go to the *currently attached* session's sink, but the new runtime does not retain that writer: its durable fallback is the command warning stream. Detached adopted work writes to the diagnostic file while another UI is active, or to the command stream after UI close. `runtimeoutput.Fallback` releases the sink lock before calling external writers (including nested fallbacks); as with UI startup, synchronous command writes must finish before a new UI takes terminal ownership.
- Invalid/omitted skills, provider debug lines, unexpected parser/engine/MCP/approval/worker/cleanup failures, stream performance telemetry, and other background diagnostics go to the file, not recurring footer notifications. Child-run progress is diagnostic-only; child failures remain surfaced through their run result. `skills validate --all` now enumerates malformed discovered manifests rather than asking `List()` (which excludes them), so skipped skills remain user-diagnosable. ChatGPT/Copilot/Grok lazy sign-in returns an actionable error if attempted during an active UI rather than painting an interactive auth prompt over the renderer; sign-in before UI startup and standalone auth commands still use the normal terminal.

The `cmd` AST guard covers direct logger and stdout/stderr calls in shared interactive worker packages and selected chat-reachable command files; named exceptions cover guarded auth flows, one-shot CLI output and unrecoverable forced exit. It inspects Go calls, not third-party internals or dynamic descriptor aliases.

## Direct output intentionally retained

- Cobra one-shot commands (including validation reports and machine-readable stdout), server/jobs logging, explicit CLI progress, and renderer-owned terminal writes. Terminal sizing via `os.Stdout.Fd()` is a read, not output.
- Interactive subprocesses use deliberate hand-off (`chat` shell release/restore, editor commands) or capture stdout/stderr as tool/provider results (`shell`, `rg`, provider CLI pipes, MCP process stderr and gist commands); browser open helpers do not inherit streams by default. `termimage` terminal probing and `/dev/tty` approval/MCP sampling summaries are terminal protocols or deliberate external interactions, not unsolicited diagnostics.
- `internal/ui/selector.go` and wizard setup write only in standalone setup/selector flows or explicit TTY interactions, not during a running chat program. The forced-interrupt `os.Exit(130)` path writes an emergency line after Bubble Tea fails to stop; no ordinary UI lifecycle is recoverable there. `cmd/ask.go` returns captured child stderr as intentional CLI output.

## Verification boundaries

Tests cover file routing, read-only diagnostic fallback, debug visibility, ordinary logger preservation, concurrent writes, exclusive ownership, open failure, footer no-leak/dedup/reattach, nested fallbacks before/during/after UI ownership, multiple switches with detached adopted writers, and validation of a malformed manifest. Full module build/test/vet, complexity guard and race checks are recorded in the PR. Static inspection cannot guarantee that future third-party loggers (or unscanned dynamic subprocesses) never write directly to their inherited descriptors; adding a new interactive worker should use `runtimeoutput` or a caller-supplied UI warning sink and test its terminal lifecycle.

`skills validate --all` enumerates valid and invalid discovered manifests while retaining first-valid precedence for duplicate names; a shadowed invalid duplicate does not replace an earlier valid skill. During explicit handover/reload there is no active UI sink, so stderr keeps its CLI behavior. The restricted diagnostics log has no automatic size cap or retention; users should rotate/delete it themselves until bounded retention is implemented. Symlink replacement between `Lstat` and `OpenFile` is possible for a same-user attacker with write access to the diagnostics directory; the directory is normally private (0700), and cross-platform no-follow semantics are out of scope for this change.
