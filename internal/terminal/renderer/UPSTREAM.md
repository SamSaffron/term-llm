## term-llm-owned divergence

This directory is the reduced terminal renderer owned by term-llm and maintained with the sibling runtime, not an independently published library. Relative to the base above, term-llm owns:

- `styled.go`: incremental `StyledString.DrawOver` behavior used by changed-row and exposed-scroll repainting, and rejection of CSI sequences carrying enough parameters to overflow the fixed parameter buffer in `x/ansi`;
- `terminal_renderer.go`, `terminal_renderer_hardscroll.go`, and renderer buffer/hash-map code: exact `HardScroll`, complete stale-row touching, wide-cell deletion correctness, output-state regressions, and per-frame line-damage records that are reset in place rather than reallocated for every line of both buffers on every render;
- `decoder.go`: sequences introduced by a single-byte 8-bit C1 control are decoded consistently with their two-byte `ESC`-prefixed form. X10 mouse reports read their payload from the last three bytes rather than a fixed offset; an abandoned OSC/APC/PM/SOS no longer resynchronizes to a fabricated `Alt+<key>` built from a data byte; an OSC without a `;` separator no longer parses the introducer bytes as its payload; the OSC give-up test no longer compares against the payload offset of the seven-bit introducer; Win32 letter casing treats Shift and CapsLock as XOR; and expanded Win32 `wRepeatCount` records mark only key presses after the initial event as repeats;
- retained cell/buffer/style/event/key/mouse/decoder/reader/poller/TTY implementations needed by Bubble Tea on Linux, macOS/BSD, and Windows;
- focused tests and benchmarks for those retained primitives and renderer paths;
- pruning documented in `../README.md`, including high-level terminal/window/console frameworks, layout/screen widgets, examples/tutorials, repository automation, and their dependencies.

Dependency-driven edits to retained upstream files (not behavioral divergence, but they will show up as local diffs when syncing):

- `key_test.go`: the kitty graphics parse expectation reads `kitty.Options.Quiet` rather than the misspelled `Quite`. As of `x/ansi v0.11.8` both fields exist, but the decoder only ever assigns `Quiet` (`q=`); `Quite` is a deprecated write-side override that wins only when non-zero. Upstream carries the same rename.

The implementation history is carried by term-llm commits and this file-level contract, not by opaque commits from a temporary import branch. When importing an upstream fix, diff it from the durable base, apply only the required production files and focused tests, preserve the owned renderer behavior above, update this base if appropriate, and follow the selective-sync and validation checklist in `../README.md`.

## Selected upstream commits landed

- `270558f35f71490525553e232304184c10f1e334` `fix(renderer): keep wrapped hyperlinks clickable on every line`: a nil pen reset now goes through the shared empty-cell update, clearing the recorded hyperlink as well as closing it on the terminal. Previously a following row or frame with the same link never reopened it. Covered red-test-first by `TestRendererHyperlinkReopensOnEachRow`, `TestRendererHyperlinkReopensOnNextFrame`, and `TestRendererHyperlinkClosesOnceAcrossUnlinkedFrame`.
- `d9e819d` `fix(render): flush trailing empty cells in renderLine` (#128): the trailing-cell buffer was only written when a later non-empty cell appeared, so a line ending in blank/styled cells lost its trailing columns when stringified. Covered by `TestRenderLineFlushesTrailingEmptyCells`. - `9b00276` `fix: handle overwrite cursor movement when cell has zero width`: the overwrite path appended a fabricated space for a column that held no cell, shifting cursor movement. Covered by `TestRelativeCursorMoveOverwriteSkipsZeroWidthCells` and the public-path `TestRendererFirstFrameHasNoPhantomSpace`. Upstream-inherited caveat: the surviving loop assumes a skipped column needs no traversal, which holds for the two column kinds this fork can produce - the virtual column before the first cell, and wide-glyph placeholders, which the owned wide-cell fallback keeps out of `putRange` - because no application path builds sparse lines (nothing outside this module calls `SetCell`). - `a5fed5c`, `7db69eb`, `6966a4f` `fix(styled): carry data-bearing escape sequences into cell content` / `only carry a sequence that actually ended` / `close two holes in what a cell may carry`: `styled.go` carries into cell content only ST-terminated APC/DCS/SOS/PM sequences, and drops OSC, CSI, other escapes and any unterminated fragment (an unterminated introducer makes the terminal swallow everything painted after it; a replayed OSC would refire clipboard writes on every repaint). Hyperlinks stay read into `Link`. Covered by `TestStyledStringEscapeCarryPolicy` (drop cases), `TestStyledStringCarriesTerminatedAPC` (positive control, green before and after) and `TestStyledStringCarriesTerminatedAPCBeforeGlyph` (a carried sequence survives the glyph that follows it, via the `pending`/`carryPending` accumulator). - `6cf7526` `fix(kitty-keyboard): modified navigation/function key releases`: the decoder no longer requires the first parameter to be `1`, so modified navigation/function key repeats and releases decode correctly. Covered by `TestParseKittyModifiedKeyReleases`.
- `043ea8a` `fix(styled): let Lines parse unbounded content` (#170): the nil-screen line-building path stopped at an empty bounds rectangle. Covered by `TestStyledStringLinesReturnsEveryLine`.
- `ae99b73` `fix(styled): allow semicolons in hyperlink URLs` (#172): `ReadLink` split on every `;` and rejected URLs containing one. Covered by `TestReadLinkPreservesSemicolonsInURL`. Upstream's explanatory comment on the three-field split was not carried over.
- `d38ea0f` (in part) `fix: paint dropped rows ... across resizes` plus `0de425e` `fix(renderer): repaint when the screen changes height`, ported fullscreen-only: `TerminalRenderer.Render` now reconciles a geometry change before diffing through `reconcileResize` - fullscreen forces a full repaint on a width shrink or any height change (a shrink rewraps, a grow refills rows from the terminal's scrollback) and resizes the retained buffer so rows added by a grow are diffed and painted like any other row - while inline mode keeps its partial clear and post-diff model resize. - `878653296cfdcb92c4b15721eedfcadfb6fd7406` `fix(renderer): erase rows a frame no longer draws after a resize`: `RenderBuffer.Resize` touches recreated columns and rows, including a shrink/grow between frames whose final geometry is unchanged. Geometry changes also bypass the no-touch early return and touch every new-frame row before the owned resize reconciliation/diff. This preserves the fullscreen clear policy and inline partial-clear/post-diff resize rather than importing upstream's damage refactor. Covered by `TestRendererResizeBetweenFramesErasesRecreatedCells` (width/height, inline/fullscreen) and `TestRendererNewGeometryRechecksUntouchedBlankRows` (fresh blank/partially touched frame); `TestRendererSwitchBuffer` now expects erasure of the stale first-row X instead of locking it in.
- `b2b0f8d`, `419da2b` (autowrap portions): the existing owned wide-cell whole-row fallback now disables autowrap for its emission and restores it afterwards, then reanchors the column with CR. Normal diffs, resize repaints and explicit erases all reach this same fallback, so no separate unguarded resize paint path is introduced. - `d231d67` `fix(renderer): keep autowrap on for a cluster at the margin`: the ordinary lower-right-cell guard no longer disables wrap for multi-codepoint cells; its follow-up `48eaef2` now cancels corner pending wrap immediately, before a subsequent raw write can scroll the fullscreen frame. `TestRendererCornerClusterLeavesNoPendingWrap` reproduces the gap left by the first port in relative and absolute modes and asserts the exact trailing cluster/CR bytes. - `243ea4b` (collapse boundary guard) plus owned empty-frame hardening: geometry changes to an empty buffer clear the previous owned frame from row zero before discarding its cells, never move to row -1, and retain the empty model so restoration remains a geometry change. Fork-local hardening (no upstream commit, landed red-test-first):
- `ProgressBarState.String()` in `uv.go` no longer panics for out-of-range values, mirroring the sibling runtime fix (`930e18c`). Covered by `TestProgressBarStateStringOutOfRange`.
- The param-overflow guard now covers DCS as well as CSI: both parse into x/ansi's fixed 32-entry buffer, and a DCS with enough parameter separators panicked identically (`\x1bP` followed by 32 semicolons). Covered by `TestStyledStringRejectsExcessiveDCSParams`.
- A string sequence (APC/DCS/SOS/PM) whose payload ends in BEL and never reaches ST is dropped up to and including the BEL, and parsing resumes after it. x/ansi only ends these sequences on ST, so it handed back the whole rest of the input as payload and swallowed the text after the BEL; the sequence cannot be carried either, because a terminal waiting for ST would then swallow the cells painted after it. ST-terminated sequences, and sequences ended by ST/CAN/SUB, are untouched. Covered by `TestStyledStringBelTerminatedSequenceKeepsFollowingText`.
- Carriage edge cases in `carryPending`/`foldPendingSequences`/`writeTrailingCell`: a carried sequence is consumed only where a cell is actually written, so it survives a truncation tail (`TestStyledStringCarriedSequenceSurvivesTruncationTail`) and an out-of-bounds glyph (`TestStyledStringFoldsSequenceForOutOfBoundsGlyph`); a sequence-only string still yields the line it was drawn to on the nil-screen `Lines()` path (`TestStyledStringLinesKeepsSequenceOnlyContent`); the trailing zero-width cell is not written outside the caller's rectangle (`TestStyledStringCarryWritesNothingOutsideBounds`, plus `FuzzStyledStringDrawStaysInBounds`, which asserts the draw never writes outside its area and never panics). Terminated DCS/SOS/PM carriage has positive coverage in `TestStyledStringCarriesTerminatedStringSequences`.

Deliberate asymmetries worth knowing when syncing:
- A fullscreen geometry change now always repaints, including a width grow (`e90e227` above); the prior policy trusted newly exposed columns to be blank. Reported terminal size changes are separately latched even if frame geometry returns to its old size before rendering.
- Upstream cursor invalidation inside `TerminalRenderer.Resize` remains unported. The owned relative-cursor anchoring contract is unchanged; the next render restores the owned cells without introducing upstream's broader position/damage refactor.
- `pending` is not folded at `\n`: a sequence before a newline rides the next line's first glyph, and folds back onto the previous line only when nothing follows. Upstream's accumulator behaves the same way.

The separately reproduced `2c536ce` boundary improvement now avoids erasing that row altogether; no extra touch is needed.
- `08f27a0` `fix(renderer): repaint the rows a hardware scroll moved`: already implemented by owned `scrolln`, which touches the entire moved range for both optimization and exact `HardScroll`. `TestRendererHardwareScrollRepaintsUntouchedRows` passes on the pre-port tree: it forces SU(2), asserts that `aa` is emitted twice (including the untouched application row), and compares every retained cell. The existing randomized `TestRendererScrollOptimUnchangedRows` covers the same invariant. No production change.
- `c0d8ed2` `fix(renderer): latch a resize against the size last reported, not the model`: no independent reproduction on this fork, whose old `Resize` updated only tab stops and could not spuriously latch. `TestRendererDuplicateResizeDoesNotRepaint` passes before and after: repeated 20x8 reports with a 20x6 frame produce no output in either mode. No standalone model-relative latch or corrective port was introduced; the newly reproduced `e90e227`/`af6533f` round-trip bug is adapted directly with last-reported-size tracking, keeping this duplicate-report control green.
- `666ce5e`, `d4534d5`: upstream input-loop races in `terminal.go`, which is pruned here. The retained owned `TerminalReader.sendBytes` already allocates a fresh array per read; no upstream high-level input-loop code is restored.
- `6b8d4ba`: OSC 7501 feature, not a renderer correctness fix; intentionally not imported.
- `a45b7c8`, `4e49372`: upstream `go.mod` housekeeping; dependency/module identity remains owned here, so no module changes imported.

- `006e29f` `fix: draw graphene clusters wider than 4 columns` (#150): unreachable in this fork. The retained width model (`ansi.GraphemeWidth` on `x/ansi v0.11.8` with `clipperhouse/displaywidth v0.11.0`) measures every printable cluster we can construct at one or two columns - a ZWJ family emoji is 2, not the 8 upstream caps - so the `case 1, 2, 3, 4` branch cannot drop a printable cluster here and no failing test could be written. Re-validated at that version pair by probing `ansi.DecodeSequence` over ZWJ sequences, tag-sequence flags, regional-indicator pairs, skin-tone joins, stacked combining marks and Devanagari clusters: the widest observed cluster is 2.
- `9836d5f` `fix(renderer): properly skip zero cells when comparing lines`: no observable difference in this fork. It becomes meaningful only with styled wide-cell placeholders, which this fork does not create.
- `c7cac3e`, `d160fe7`, `f5cce66` (wide-glyph placeholder/cursor-drift family) and `eb96d54` (relative-cursor row clamp): these target rendering behavior this fork deliberately rewrote, and land only with a failing case reproduced in this tree first. `eb96d54` has no reproduction (a 5->2 inline shrink emits its cursor-up and leaves the model row correct); the resize repaint half of the family landed as the fullscreen-only port of `d38ea0f`/`0de425e` above; `c7cac3e` has no reproduction because this fork's placeholders are plain zero cells and the styled-placeholder case cannot be built. The reproduced autowrap portion of `b2b0f8d`, with the shared-path requirement from `419da2b`, is now selected above; the rest of the drift family remains unported.
- `36d053f` (SGR-pixel mouse encoding) is a feature, and `3a9b1e4` (auto-enable grapheme mode) targets upstream `terminal.go`/`terminal_screen.go`, which are pruned here.
